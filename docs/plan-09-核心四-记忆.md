# plan-09 · 核心四：记忆（Memory）—— **可选能力**

| 项 | 值 |
|---|---|
| 对应 PRD | §8.4 记忆 |
| 阶段 | Phase 5 |
| 优先级 | **P2（尽力而为，允许缺失）** |
| 依赖 | plan-03、plan-05 |
| 规模档 | 中（持久化与合规成本高） |

---

## 1. 定位说明

**本能力是四个核心中唯一允许"没有也无所谓"的。** 原因：

1. 跨会话学情记忆需要**持久化存储**，与当前"纯离线、单端口、零外部依赖"的部署形态冲突；
2. 涉及**学习者个人信息**长期保存，需额外的隐私合规设计与用户授权流程；
3. 收益不确定——单次会话内的学情闭环已能覆盖大部分教学价值。

**因此：L0/L1 必做（成本极低），L2/L3 视情况做，允许永久不做。**

> ### 范围决策（2026-10-14，用户确认）
>
> **本次不做学情记忆持久化。** L2 / L3 整体移出当前范围，登记为「后续按需启用」。
> 本 plan 当前只交付 **L0 / L1**（会话内、不落盘、零隐私风险）。
>
> 这意味着：**记忆不再是本项目的阻塞项或风险项**，四个核心中它的范围被压到最小。
> 若未来需要跨会话学情，本 plan 后文的方案与六道合规门可直接启用，无需重构。

---

## 2. 记忆分层

| 层 | 内容 | 存储 | 生命周期 | 优先级 |
|---|---|---|---|---|
| **L0 会话上下文** | 最近 6 轮对话 | 内存 | 请求结束即弃 | P0 [实证] 已有 |
| **L1 会话内学情** | 本次会话的错题、答题记录、掌握度 | 内存 | 会话结束即弃 | P0 |
| **L2 学习者画像** | 跨会话的掌握度向量、历史错题 | 需持久化 | 用户可删除 | P2（可选） |
| **L3 长期知识曲线** | 知识点掌握随时间的变化 | 需持久化 | 用户可删除 | P3（可选，可不做） |

---

## 3. L0 / L1（必做，无隐私风险）

### 3.1 设计

```python
session = {
    "history": [...],          # L0：最多 6 轮，超出滚动丢弃
    "quiz_log": [...],         # L1：本次会话答题记录
    "mastery": {...},          # L1：本次会话掌握度
}
```

### 3.2 硬约束

| 编号 | 约束 |
|---|---|
| M-1 | 默认**不落盘**；进程结束即清除 |
| M-2 | 会话状态不可在请求间泄漏（无全局可变状态） |
| M-3 | 历史长度上限 6 轮（沿用前身实现） |
| M-4 | 记忆内容必须可被用户查看与清除 |

### 3.3 验收

- 单测：两个不同会话的错题互不干扰；
- 单测：会话结束后不残留任何内存引用；
- 单测：历史超过 6 轮时按滚动窗口丢弃。

---

## 4. L2 / L3（可选，需先过合规门）

### 4.1 前置门禁（任一不满足则不做）

| 门禁 | 要求 |
|---|---|
| G-1 授权 | 用户显式同意才能持久化 |
| G-2 最小化 | 只存学情，**禁止存姓名、手机号、学校、身份证、聊天原文** |
| G-3 可删除 | 提供"清除我的学习记录"入口，且真实删除 |
| G-4 隔离 | 匿名 learner_id（随机 UUID），不与任何身份信息关联 |
| G-5 透明 | 明确告知"我们记住了什么、记在哪、怎么删" |
| G-6 可关闭 | 默认关闭持久化，用户主动开启 |

### 4.2 存储方案（若启用）

| 方案 | 适用 | 说明 |
|---|---|---|
| 本地 SQLite | 单机 / 单用户 | 零外部依赖，优先 |
| 云端 KV / DB | 多设备 | 需引入云服务，增加复杂度 |

**优先本地 SQLite。** 若最终需要云端，须先确认部署环境的持久化能力与合规要求。

### 4.3 结构（若启用）

```json
{
  "learner_id": "anon-uuid",
  "mastery": {"kp.civil.contract.validity": {"m": 0.41, "n": 12, "updated": 0}},
  "wrong_log": [{"qid": "q.civil.0001", "ts": 0, "kp": ["..."]}],
  "consent": {"granted": true, "at": 0, "scope": "mastery_only"}
}
```

### 4.4 验收（若启用）

| 项 | 标准 |
|---|---|
| A1 | 未授权时零持久化 |
| A2 | 存储内容不含任何 PII（自动扫描为零） |
| A3 | 删除请求后 24h 内数据不可恢复 |
| A4 | 关闭持久化后功能仍可用（降级为会话内） |

## 5. 任务分解

| ID | 任务 | 优先级 |
|---|---|---|
| T9.1 | 会话状态容器（无全局可变状态） | P0 |
| T9.2 | L1 学情记录（错题、掌握度） | P0 |
| T9.3 | 记忆查看 / 清除接口 | P0 |
| T9.4 | 合规门禁清单落文档 | P1 |
| T9.5 | 本地 SQLite 持久化（**需用户确认后才做**） | P2 |
| T9.6 | PII 扫描检查器 | P1（若做 T9.5） |

---

## 6. 明确不做

- ❌ 不做长期记忆的"自动学习偏好推断"
- ❌ 不记忆任何聊天原文
- ❌ 不做跨用户的共享记忆
- ❌ 不在未授权时留任何痕迹

---

## 7. 依赖与风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 隐私合规风险 | 高 | 默认关闭；G-1~G-6 门禁全过才做 |
| 持久化破坏"纯离线"部署优势 | 中 | 优先本地 SQLite；不做则功能不缺失 |
| 记忆污染导致错误画像 | 中 | 提供清除入口；掌握度带时效衰减 |
| 范围蔓延 | 中 | 本计划优先级明确为 P2，**不得阻塞主线** |

---

## 8. 结论

**本计划的最小可交付是：L0 + L1（会话内记忆）+ 查看/清除接口。** 这已能满足"学→练→诊断→再学"的会话内闭环。L2/L3 在有明确需求且合规门禁通过后再启动。
