## 1. 目标

把全部约束写成**代码可执行、可断言、可清零**的规则。文档里的一句话如果没有对应的实现位置和评测断言，就不算规则。

## 2. 规则全集

| 编号 | 规则 | 实现位置 | 断言 |

| F1 | 禁止编造法条：任何条款编号与原文必须来自知识库，一字不改 | `statutes.py` + `tools/evidence.py` | G1/G2 通过率 100% |

### 2.3 合规规则（C）

| 编号 | 规则 | 实现位置 | 断言 |

| 编号 | 规则 | 实现位置 | 断言 |

### 2.5 隔离与确定性规则（D）

| 编号 | 规则 | 实现位置 | 断言 |
|---|---|---|---|
| D1 | 禁止写死回答：不同问题必须得到不同结论与建议 | 全局 | V1 |

| D4 | 判定链不得使用 non-deterministic 工具 | `tools/registry.py` | 违反数 = 0 |

### 2.6 评测规则（E）

| 编号 | 规则 | 实现位置 | 断言 |
|---|---|---|---|
| E1 | 自动检查必须清零，不得加白名单或替身 | `scripts/*` | 问题计数 = 0 |
| E2 | 每个 FR 至少 3 条回归用例 | `tests/` | 覆盖缺口 = 0 |
| E3 | 引用核验必须独立实现（不与生成共用同一取数逻辑） | `run_eval.py` | 代码审查 |

---

## 3. 规则优先级

冲突时按此顺序裁决：

```
事实规则 F  >  合规规则 C  >  教学规则 T  >  路由规则 R  >  隔离规则 D
```

例：用户要求"帮我写起诉状" —— C1 拒答优先于用户意图；但按 C4，降级为"整理案情要点 + 知识点清单"。
