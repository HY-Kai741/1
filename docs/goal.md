## 0. 一句话能力描述（可防守）

> **这个 Agent 接收大学生与法考学习者的法律学习请求（概念提问、概念辨析、案例练习、刷题测评、学情查询），用于完成法律知识的讲解、训练与学情诊断，输出带法条溯源的教学内容与学习建议，不处理个案法律咨询、法律文书生成与诉讼策略。**

这句话必须同时守住四件事：**教什么、怎么教、给什么、不碰什么**。

## 1. 意图捕获（Intent）

| 项 | 内容 |
|---|---|
| **长期接住的重复任务** | 学生反复发生的"看不懂 → 练不会 → 不知道自己哪儿不会"三段循环 |
| **用户实际给的输入** | 自然语言提问、题目文本、自己的作答、自选知识点或部门法、上传的课程材料（[计划]） |
| **做好的交付** | 带法条原文与出处的讲解 / 概念对照表 / 分层案例引导 / 判题与解析 / 错题归因 / 掌握度 / 下一步学习序列 |
| **不该触发的请求** | 个案法律咨询、合同审查、文书起草、诉讼策略、律师匹配、非法律类答疑 |
| **最重要的标准** | **事实一致性优先**（零编造法条）> 教学有效性 > 速度 > 成本 |
| **可借鉴的公开参考** | JEC-QA（题库与题型标签）、Legal-Exam-Skills-AI（阶层论引导与批改维度）、Duetoday（解释即转主动回忆）、布鲁姆认知模型与知识图谱路径推荐 |
| **已有资产** | 前身法律问答 Agent：本地法条库 378 部 / 23,995 条、8 阶段确定性流水线、23 条评测用例、已上线服务 |

## 2. 领域判定（不可动摇）

依 `目标.md` 五条标准（目标 / 用户 / 内容 / 交互 / 监管），本产品判定为 **法律教育 / 普法教育**，**不是法律服务**。

**判定后果（硬边界）：**

| 允许 | 禁止 |
|---|---|
| 知识讲解、概念辨析、案例教学 | 个案法律意见 |
| 刷题、判题、错题诊断、掌握度 | 合同审查 |
| 学习路径与知识点导航 | 诉讼策略 |
| 法条检索与溯源 | 法律文书起草 |
| 学情统计与反馈 | 律师匹配 / 收费咨询 |

**边界处理方式：个案咨询不硬拒，降级为教学。** 用户问"我的押金能退吗"，系统答"押金能否退还在法律上取决于 X/Y/Z 三个要件，逐个讲，并配一道同类题"。

## 4. 触发与不触发边界

### 4.1 应该触发（should-trigger）

- "什么是善意取得？"
- "定金和订金有什么区别？"
- "帮我分析一下这个案例"
- "给我出几道合同的题"
- "我哪部分比较薄弱？"
- "劳动法应该按什么顺序学？"

### 4.2 不应该触发（should-not-trigger）

- "我这个押金还能要回来吗？"（个案 → 降级为教学，不判定）
- "帮我写一份起诉状"
- "我这个案子怎么打"
- "帮我看看这份合同有没有坑"
- "推荐个靠谱的律师"
- "今天天气怎样"

### 4.3 近邻请求（near-neighbor，易混）

| 请求 | 判定 | 理由 |
|---|---|---|
| "法条里第 143 条说了什么" | ✅ 触发 | 知识查询 |
| "我这事适用哪条" | ⚠️ 降级 | 个案，转知识点讲解 |
| "这道题答案是什么" | ✅ 触发 | 测评 |
| "这题我为什么错" | ✅ 触发 | 诊断 |
| "帮我改改我的答案" | ✅ 触发 | 主观题初评 |

## 5. 四大核心

### 5.1 工具（Tools）

| 类别 | 工具 | 状态 |
|---|---|---|
| 知识检索 | `law.search` / `law.get` / `law.resolve` | [实证] |
| 内容核验 | `law.verify` / `evidence.check` | [实证] |
| 知识点 | `kp.tree` / `kp.get` / `kp.search` | [计划] |
| 题库 | `q.search` / `q.get` / `case.get` | [计划] |
| 测评 | `grade.objective` / `grade.subjective` / `paper.build` | [计划] |
| 学情 | `diagnose.run` / `mastery.compute` / `path.plan` | [计划] |
| 可观测 | `obs.trace` / `obs.redact` | [实证] |

**铁律**：Agent 不得直连数据，一切经工具；一切含法条引用的输出必须过 `evidence.check`。详见 `plan-06`。

### 5.2 大模型（LLM）

**立场：模型是措辞层，不是事实层。默认关闭。**

| 用途 | 用模型 |
|---|---|
| 法条检索 / 原文输出 / 客观题判题 / 掌握度 / 路径 | ❌ |
| 答疑措辞润色 / 辨析文本组织 | ✅ 仅改措辞 |
| 主观题逻辑校验 | ⚠️ 辅助信号，不单独定分 |
| 案例生成 / 出题 | ⚠️ 模板驱动，须过规则校验 |

[实证] 当前线上 `llm.enabled = false`，全链路零模型调用。详见 `plan-07`。

### 5.3 规则（Rules）

六类规则集：**事实 F / 教学 T / 合规 C / 路由 R / 隔离与确定性 D / 评测 E**。

* 事实规则优先于一切（零编造法条、可溯源、结构完整、教学声明）；
* 合规规则次之（拒答个案意见/文书/策略/伪造证据，教学声明必须出现）；
* 每条规则必须有**实现位置 + 可清零断言**，否则不算规则。

详见 `plan-08`。

### 5.4 记忆（Memory）—— 可选

| 层 | 内容 | 优先级 |
|---|---|---|
| L0 会话上下文（6 轮） | 对话历史 | P0 [实证] |
| L1 会话内学情 | 错题、掌握度 | P0 |
| L2 跨会话画像 | 掌握度向量、历史错题 | **P2 · 可选** |
| L3 长期曲线 | 掌握随时间变化 | P3 · 可不做 |

**本核心允许缺失而不阻塞发布。** 若做 L2/L3，必须先过六道合规门（授权、最小化、可删除、隔离、透明、可关闭）。详见 `plan-09`。

## 6. 工作流（Workflow）

```
意图路由 ─► 范围判定 ─► 知识检索 ─► 内容生成 ─► 证据核验 ─► 组装输出
（Orchestrator）（guard/scope）（kp/law/q）（学科/能力 Agent）（强制）  （presenter）
```

| 意图 | 编排 |
|---|---|
| 概念学习 | 学科 Agent → 证据核验 → 输出 |
| 概念辨析 | 知识点导航 → 学科 Agent → 证据核验 |
| 案例教学 | 知识点导航 → 分层引导 →（用户作答）→ 批改 |
| 刷题 | 出题 →（用户作答）→ 判题 → 诊断 → 更新掌握度 |
| 学情 | 诊断 → 掌握度 → 路径 |

**决策点**：① 是否在范围内；② 是否有足够数据（无数据则明说"未收录"，不臆造）；③ 是否需要引导还是直接给答案；④ 是否需要降级。

## 7. 输出契约（Output Contract）

**教学类输出必须包含：**

1. 讲解 / 解析主体；（必）
2. 法条依据（法律名称 + 条号 + 原文，逐字引用）；（必）
3. 知识点标注（挂靠的知识点）；（必）
4. 教学用途声明；（必）
5. 下一步建议（学什么 / 练什么）；（必）
6. 学情标注（若涉及测评，必须标「AI 初评」）。（条件必）

**禁止出现在输出中：** 个案结论、绝对判断、法律文书模板、无来源的法条、无证据的能力声称。

## 9. 证据边界（Evidence Boundary）

### 9.1 有证据（[实证]）

- 法条库规模 378 部 / 23,995 条，本地离线可查；
- 8 阶段确定性流水线可运行；
- 23 条评测用例全绿（eval 23/23、variation 14/14、smoke 16/16）；
- 零模型调用即可完整运行；
- 线上服务可用（`/api/health` 正常）。

### 9.2 仅计划（[计划]）

- 多 Agent 架构、知识点体系、题库、判题、掌握度、路径推荐；
- 司法解释扩充；
- 工具注册表与门禁检查器。

### 9.3 未验证假设（[假设]）

- 教学效果提升（同知识点正确率 +15%）**无证据**；
- 错题归因认可率 ≥ 70% **无证据**；
- 路径完成率 ≥ 50% **无证据**；
- "零编造 + 确定性内核"优于纯生成式教学产品 **未做公平对比**。

> **对外声明纪律**：以上 [假设] 指标在埋点回填前，不得写入任何对外文案。`check_claims.py` 强制拦截。

### 9.4 缺失证据（missing evidence）

- JEC-QA 及各题库的**实际许可条款未核实**——发布前必须确认，否则只上线自建题库版本；
- 教师端需求未确认；
- 是否引入付费 LLM 未确认。
