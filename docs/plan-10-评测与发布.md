---

## 1. 目标

建立**可清零**的评测体系，并把发布做成可复现、可回滚的流程。

**核心原则（沿用 `qiaomu-meta-skill` 第 19 条）：自动检查的输出是可数的问题计数，通过标准是 0，不是"大致没问题"。**

---

| 层 | 内容 | 门槛 | 现状 |
|---|---|---|---|
| L1 事实 | 法条引用回库核验（G1/G2） | 100% | [实证] 已有 |

## 3. 用例组织

```
tests/
├── cases/
│   ├── fact.jsonl          # L1/L2
│   ├── safety.jsonl        # L3
│   ├── isolation.jsonl     # L4
│   ├── teaching.jsonl      # L5
│   ├── grading.jsonl       # L6
│   ├── rubric_human.jsonl  # L7（人工抽检记录）
│   ├── mastery.jsonl       # L8
│   ├── path.jsonl          # L9
│   └── trace.jsonl         # L10
└── run_all.py              # 一次跑全层，输出问题计数
```

**每个功能需求（FR-1 ~ FR-10）至少 3 条用例**，覆盖缺口必须为 0。

---

## 4. 门禁脚本

| 脚本 | 检查 | 通过标准 |
|---|---|---|
| `run_all.py` | 全层用例 | 失败数 = 0 |
| `check_no_direct_access.py` | Agent 是否绕过工具直连数据 | 违规数 = 0 |
| `check_determinism.py` | 判定链是否使用非确定性工具 | 违规数 = 0 |
| `check_evidence.py` | 输出是否全部过证据核验 | 绕过数 = 0 |
| `check_no_absolute.py` | 绝对判断词 | 命中数 = 0 |
| `check_degradation.py` | 是否有静默降级 | 静默数 = 0 |
| `check_pii.py` | 存储/日志是否含 PII | 命中数 = 0 |
| `check_claims.py` | 对外文案是否含无证据声明 | 违规数 = 0 |

**所有脚本必须可清零。禁止为通过检查而加白名单、偏置或替身。**

---

## 5. 人工评测（不可省略的两档）

| 档 | 内容 | 标准 |
|---|---|---|
| 1× | 整体可读性 | 一份完整教学输出能被目标用户读懂 |
| 4× | 局部质量 | 法条引用、采分点标注、掌握度徽标在细节上经得起看 |

**主观题评分另需人工抽检**：随机抽 30 条，人工评分与 AI 初评比对，一致率 ≥ 90%。

---

## 6. 发布流程

```
1. 本地门禁全绿（run_all.py + 全部 check_*.py 清零）
2. 冻结版本号与数据版本
3. 部署到 WorkBuddy
4. 冒烟测试（HTTP + 流式）
5. 线上自检：/api/health、5 个典型问题端到端
6. 记录发布产物与回滚点
```

### 6.1 回滚

| 触发 | 动作 |
|---|---|
| 线上事实性错误 | 立即回滚到上一版本 |
| 延迟超标 | 回滚或降级到纯确定性路径 |
| 数据异常 | 回滚数据版本 |

**回滚点必须在发布前记录**（保存上一版本的数据文件与代码快照）。

| 指标 | 采集方式 | 目标 |

| 错题归因认可率 | 用户反馈 | [假设] ≥ 70% |
| 路径完成率 | 埋点 | [假设] ≥ 50% |

## 10. 依赖与风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 为过门禁而放宽标准 | 高 | 明确禁止白名单/替身；代码评审拦截；门禁脚本独立于业务代码实现 |
| 人工评测被跳过 | 中 | 列为发布前置条件，未完成不得发布 |
| 指标无证据就对外声明 | 中 | `check_claims.py` 强制拦截；未回填指标一律标 [假设] |
| 多 Agent 后用例维护成本上升 | 中 | 用例按层组织，层与 Agent 解耦 |
