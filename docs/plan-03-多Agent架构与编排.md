# plan-03 · 多 Agent 架构与编排

| 项 | 值 |
|---|---|
| 对应 PRD | §5 产品形态、FR-1~FR-10 |
| 阶段 | Phase 2 |
| 优先级 | P0 |
| 依赖 | plan-01、plan-02 |
| 规模档 | 大（架构重构，需分档推进） |

---

## 1. 目标

把前身"单一确定性流水线"演进为**多 Agent 架构**：一个 Orchestrator 负责路由与编排，学科 Agent 与能力 Agent 各司其职，全部共享同一套知识层与证据层。

**核心不变式：架构变了，事实约束不变。** 任何 Agent 输出的法条引用仍须回库逐字核验（沿用 C1/G1/G2）。

---

## 2. 架构

```
                        用户输入
                           │
                 ┌─────────▼──────────┐
                 │   Orchestrator     │  意图路由 / 会话编排 / 降级 / 预算
                 │   （无知识、无状态） │
                 └──┬──────────────┬──┘
        ┌───────────┘              └────────────┐
┌───────▼─────────┐                    ┌────────▼─────────┐
│ 学科 Agent × N   │                    │ 能力 Agent × M    │
│ 民法/刑法/民诉/   │                    │ 知识点导航        │
│ 刑诉/行政/商经知/ │                    │ 出题 Agent        │
│ 理论法/三国法     │                    │ 判题 Agent        │
└───────┬─────────┘                    │ 诊断 Agent        │
        │                              │ 掌握度 Agent      │
        │                              │ 路径 Agent        │
        │                              └────────┬─────────┘
        └──────────────┬───────────────────────┘
              ┌────────▼────────┐   ┌───────────────┐
              │  知识层（只读）  │   │  证据层（强制） │
              │  法条/知识点/题库│   │  引用回库核验   │
              └─────────────────┘   └───────────────┘
```

---

## 3. Agent 清单与契约

| Agent | 类型 | 输入 | 输出 | 是否用模型 |
|---|---|---|---|---|
| Orchestrator | 总控 | 用户消息 + 会话状态 | 路由决策 + 编排计划 | ❌ |
| 学科 Agent（8 个） | 学科 | 消息 + 知识点上下文 | 讲解 / 辨析 / 案例引导 | 措辞层可选 |
| 知识点导航 Agent | 能力 | 关键词 / 路径 | 知识点树 + 关联法条 | ❌ |
| 出题 Agent | 能力 | 知识点 + 难度 + 题型 | 题目（模板驱动） | 受限 |
| 判题 Agent | 能力 | 题目 + 用户答案 | 对错 + 解析 + 采分点命中 | ❌（客观）/ 受限（主观） |
| 诊断 Agent | 能力 | 错题集 | 归因（薄弱知识点） | ❌ |
| 掌握度 Agent | 能力 | 答题记录 | 知识点掌握度 | ❌ |
| 路径 Agent | 能力 | 掌握度 + 目标 | 学习序列 | ❌ |
| 证据 Agent | 横切 | 任意含引用的输出 | 核验结果（通过 / 拒绝） | ❌ |

**设计约束：除"措辞层"外，所有 Agent 的核心判定必须是纯函数**——可单测、可重放、零成本。

## 4. 编排协议

### 4.1 统一消息信封

```json
{
  "trace_id": "edu_xxx",
  "session": {"learner_id": null, "history": []},
  "task": {"intent": "answer|quiz|diagnose|path", "subject": "civil", "kp": "kp.civil.contract.validity"},
  "payload": {},
  "constraints": {"max_latency_ms": 800, "allow_llm": false}
}
```

### 4.2 编排规则

| 意图 | 编排 |
|---|---|
| 概念学习 | 学科 Agent → 证据 Agent → 输出 |
| 概念辨析 | 知识点导航 → 学科 Agent → 证据 Agent |
| 案例教学 | 知识点导航 → 学科 Agent（分层） → 判题 Agent（用户答后） |
| 刷题 | 出题 Agent → 用户作答 → 判题 Agent → 诊断 Agent |
| 学情查询 | 诊断 Agent → 掌握度 Agent → 路径 Agent |

### 4.3 降级策略

| 故障 | 降级 |
|---|---|
| 学科 Agent 不可用 | 落到"通用知识检索 + 法条原文" |
| 判题 Agent 不可用 | 只给参考答案，不给分 |
| 掌握度不可用 | 只给错题清单 |
| 模型不可用 | 全部走模板文案（**默认路径**） |

**降级必须显式告知用户**，不得静默降级。

## 6. 验收标准

| 项 | 标准 | 可验证 |
|---|---|---|
| A1 | Orchestrator 无知识耦合 | 代码中不出现法条字面量 |
| A2 | 所有引用经证据 Agent | 绕过证据层的输出数 = 0 |
| A3 | 前身 23 条用例在新架构下全绿 | 通过率 100% |
| A4 | 降级路径全部有覆盖 | 每个降级分支 ≥ 1 条用例 |
| A5 | 链路可重放 | 同输入恒定输出 |
| A6 | trace 贯穿全部 Agent | 每个 Agent 都有 span |

## 7. 依赖与风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 过度设计，2 个 Agent 能解决却拆 13 个 | 高 | 分档推进；每档必须有可运行版本；Agent 只在"独立性可验证"时才拆出 |
| 多 Agent 带来延迟叠加 | 中 | Orchestrator 内并行化无依赖的 Agent 调用 |
| 状态在 Agent 间泄漏 | 中 | 消息信封不可变；Agent 只读不写共享状态 |
| 前身功能回归 | 中 | 迁移前先冻结 23 条基线用例 |
