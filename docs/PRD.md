## 1. 背景与领域定位

### 1.1 现状

前身产品是一个**确定性法律常识问答 Agent**：用户描述具体纠纷，系统识别场景、检索法条原文、给出通俗解释与行动建议。[实证] 技术基线：本地法条库 378 部法律 / 23,995 条现行条文，5 个专项场景 / 35 条映射法条，8 阶段固定流水线，23 条评测用例全绿，P95 约 290 ms，零模型调用。

### 1.2 领域判定：本产品属于「法律教育」

依 `目标.md` 给出的五条判断标准逐条判定：

| 判断标准 | 现状（问答版） | 本产品（教育版） | 判定 |
|---|---|---|---|
| 目标 | 解决具体事务 | 知识传授与能力训练 | **教育** |
| 用户 | 当事人 | 学习者（学生 / 考生 / 公众） | **教育** |
| 内容 | 个案化、咨询化 | 课程化、体系化（知识点 / 学习路径） | **教育** |
| 交互 | 检索、生成、建议 | 教学反馈、测评、掌握度 | **教育** |
| 监管 | 律师执业 / 法律咨询资质 | 教育 App / 培训资质 | **教育** |

**结论：本产品定位为「法律教育 / 普法教育」，不是「法律服务」。** 这一定位带来两条不可逾越的边界：

1. **不做个案法律意见、合同审查、诉讼策略、文书生成**——一旦做，就落入法律服务监管范畴；
2. **免责声明从"不构成法律意见"扩展为"教学用途声明"**，且必须显式声明不替代教师评价。

### 1.3 为什么必须转型

现有问答形态有一个结构性缺陷：**它只回答，不教学**。[实证] 用户问一次、得到一次答案，系统不记录他学过什么、哪里不会、下一步该学什么。这正是 `目标.md` 要求补齐的四项能力——学习路径、知识点体系、错题反馈、掌握度评估。

## 2. 产品目标

### 2.1 一句话定位

> 一个面向大学生与法考考生的**法律教育 Agent 群**：把法条讲成知识、把知识练成题、把错题变成诊断、把诊断变成下一步学习路径。

### 2.2 三层能力目标

| 层 | 用户能做什么 | 对应功能 |
|---|---|---|
| 教 | 看懂概念、辨析易混点、跟案例走一遍推理 | FR-1 / FR-2 / FR-3 |
| 练 | 刷题、得到判题与解析、拿到主观题初评 | FR-4 |
| 跟 | 看到薄弱点、掌握度、下一步学什么 | FR-5 / FR-6 / FR-7 / FR-8 |

### 2.3 非目标（明确排除）

- ❌ 个案法律意见、代写文书、诉讼策略
- ❌ 律师匹配、法律服务撮合、收费咨询
- ❌ 用模型生成法条或司法解释文本
- ❌ 用 AI 分数替代课程成绩或教师资格评价

## 3. 目标用户与核心场景

| 角色 | 主要诉求 | 典型场景 | 优先级 |
|---|---|---|---|
| 在校本科生（法学） | 课程跟学、概念辨析、案例练习 | "善意取得和善意第三人是一回事吗" | P0 |
| 在校本科生（非法学） | 通识普法、生活场景理解 | "兼职被欠薪，法律怎么规定的" | P0 |
| 法考 / 法硕考生 | 刷题、错题诊断、主观题带练 | "刷完这组题，我哪些考点不行" | P0 |
| 公众学习者 | 按主题自学、建立常识框架 | "我想系统了解劳动法" | P1 |
| 教师 / 助教 | 布置练习、看班级掌握度 | "看看这个知识点的整体正确率" | P2 |

**主力用户**：法学本科生 + 法考考生。**次级**：非法学本科生。

## 5. 产品形态：多 Agent 架构

目标形态是多 Agent（`目标.md` 明确要求）。分三层：

```
                    ┌──────────────────────────────┐
                    │   Orchestrator（总控）        │
                    │   意图路由 · 会话编排 · 降级    │
                    └───────┬──────────────┬───────┘
            ┌───────────────┘              └───────────────┐
    ┌───────▼────────┐                            ┌────────▼───────┐
    │  学科 Agent 群  │                            │  能力 Agent 群  │
    │  民法 / 刑法     │                            │  知识点导航     │
    │  诉讼法 / 商经   │                            │  出题与判题     │
    │  理论法 / 三国法 │                            │  错题诊断       │
    └───────┬────────┘                            │  掌握度评估     │
            └──────────────┬──────────────┬────────┘  路径推荐       │
                    ┌──────▼──────┐  ┌────▼─────────┐  └────────┬───────┘
                    │  知识层      │  │  证据层       │           │
                    │  法条库      │  │  来源溯源     │◄──────────┘
                    │  知识点图谱  │  │  引用核验     │
                    │  题库        │  └──────────────┘
                    └─────────────┘
```

设计要点：
- **Orchestrator 不承载知识**，只做路由与编排，可被单测；
- **学科 Agent 共享同一套知识层与证据层**，避免每个学科各自造法条；
- **能力 Agent 是横切关注点**，独立于学科，可被任意学科复用；
- **证据层是硬约束**：任何 Agent 输出的法条引用都必须回库逐字核验（沿用前身 C1/G1/G2 机制）。

详见 `plan-03 多 Agent 架构与编排`。

## 6. 功能需求（FR）

| ID | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-1 | 学科答疑 | 按 8 大部门法组织答疑，答案含法条原文 + 来源标注 + 关联考点 | P0 |
| FR-2 | 概念辨析 | 易混概念对照（如"定金 vs 订金""正当防卫 vs 紧急避险"），输出对比表 + 区分标准 + 典型例 | P0 |
| FR-3 | 案例教学 | 分层引导式案例分析，**先给提示后给答案**，用户先答再批改 | P0 |
| FR-4 | 刷题测评 | 客观题（单选/多选/不定项）判题 + 解析；主观题三层初评（拆解→采分点→逻辑） | P0 |
| FR-5 | 错题诊断 | 按知识点聚合错题，输出"错在哪一类"而非"错了哪几道" | P0 |
| FR-6 | 掌握度评估 | 知识点级掌握度（正确率 × 难度 × 时效衰减），可视化 | P0 |
| FR-7 | 学习路径推荐 | 基于掌握度生成下一步学习序列，已掌握（≥阈值）的不再出现 | P1 |
| FR-8 | 知识点体系导航 | 部门法 → 章 → 节 → 知识点 → 法条 的多级导航 | P1 |
| FR-9 | 来源溯源 | 任一条法条 / 解析可点击回到原文出处与法条编号 | P0 |
| FR-10 | 学情记忆 | 跨会话记住学习者水平、错题、偏好（**可选能力**，见 §8.4） | P2 |

**FR-1 ~ FR-9 为必做；FR-10 为尽力而为，允许缺失而不阻塞发布。**

## 7. 非功能需求（NFR）

| ID | 需求 | 验收标准 |
|---|---|---|
| NFR-1 | 事实性 | 任何法条引用必须回库核验存在且逐字一致，命中率 100%（沿用前身 G1/G2） |
| NFR-2 | 可溯源 | 每条法条带 `law_name` + `article_no` + `article_id` |
| NFR-3 | 合规边界 | 拒答个案法律意见 / 文书生成 / 伪造证据等；命中率 100%（沿用前身评测 A1–A7） |
| NFR-4 | 教学免责 | 每次输出含"教学用途"声明，且显式声明 AI 评分不替代教师评价 |
| NFR-5 | 性能 | 答疑 P95 ≤ 800 ms；判题 P95 ≤ 300 ms（本地确定性路径） |
| NFR-6 | 确定性 | 同一输入恒定输出；教学判定不引入随机 |
| NFR-7 | 可观测 | 全链路 trace_id + 阶段埋点 + PII 脱敏 |
| NFR-8 | 可评测 | 每个 FR 至少 3 条回归用例；自动检查必须清零 |
| NFR-9 | 数据合规 | 只使用许可明确的数据源；未成年人内容分级 |

## 8. Agent 四大核心

### 8.1 工具（Tools）

| 类别 | 工具 | 现状 |
|---|---|---|
| 知识检索 | 法条检索（映射 + BM25）、知识点检索、题库检索 | 法条检索 [实证] |
| 内容核验 | 引用回库核验、原文一致性校验 | [实证] |
| 教学 | 概念对照生成、案例生成、分层提示 | [计划] |
| 测评 | 判题、采分点匹配、逻辑校验、掌握度计算 | [计划] |
| 学情 | 错题聚合、画像统计、路径排序 | [计划] |
| 可观测 | trace、指标、脱敏 | [实证] |

原则：**能确定性求解的绝不用模型**（沿用前身架构哲学）。详见 `plan-06`。

### 8.2 大模型（LLM）

| 用途 | 是否用模型 | 理由 |
|---|---|---|
| 法条检索与引用 | ❌ 绝不用 | 事实性硬约束，必须回库 |
| 判题（客观题） | ❌ 不用 | 标准答案确定 |
| 答疑措辞润色 | ✅ 可选 | 仅改写措辞，不改事实 |
| 概念辨析文本组织 | ✅ 可选 | 内容来自知识点库，模型只做组织 |
| 案例事实生成 | ⚠️ 受限 | 必须由模板/题库驱动，模型只填充，**不得生成法条** |
| 主观题初评 | ⚠️ 受限 | 采分点匹配走确定性规则，模型只做逻辑校验辅助，**必须标注"AI 初评"** |

原则：**模型是措辞层，不是事实层**。默认关闭（沿用前身 `LLM_API_KEY` 开关）。详见 `plan-07`。

### 8.3 规则（Rules）

| 类别 | 内容 |
|---|---|
| 事实规则 | C1 零编造法条、C2 结构完整、来源必须可溯源 |
| 教学规则 | 先提示后答案、不给绝对判断、不代替用户思考、难度渐进 |
| 合规规则 | 拒答个案意见 / 文书 / 伪造证据 / 索取隐私；教学用途声明 |
| 路由规则 | 意图由用户输入决定，外部参数仅作兜底、一次性 |
| 隔离规则 | 禁止写死回答；同输入恒定、异输入必须不同 |
| 评测规则 | 自动检查清零；AI 评分必须可解释、可复核 |

详见 `plan-08`。

### 8.4 记忆（Memory）——可选能力

**明确降级为 P2。** 理由：跨会话学情记忆需要持久化存储与隐私合规设计，实现成本高、收益不确定。

| 层级 | 内容 | 存储 | 状态 |
|---|---|---|---|
| L0 会话内 | 当前对话上下文（最多 6 轮） | 内存 | [实证] 已有 |
| L1 会话内学情 | 本次会话的错题与掌握度 | 内存 | [计划] |
| L2 跨会话 | 学习者画像、历史错题 | 需持久化 | [计划 · 可选] |
| L3 长期知识 | 知识点掌握曲线 | 需持久化 | [计划 · 可选] |

**硬要求**：任何记忆能力都必须是"可关闭"的；不记忆敏感个人信息；记忆内容必须可查看、可删除。详见 `plan-09`。

## 10. 评测体系

| 层 | 内容 | 门槛 |
|---|---|---|
| 事实层 | 法条引用回库核验（G1/G2） | 100% 通过 |
| 结构层 | 输出结构完整性（G3/G4） | 100% 通过 |
| 安全层 | 拒答红线、注入拦截、无绝对判断（G5/A1–A7） | 100% 通过 |
| 隔离层 | 不同问题不同答案、同输入恒定（V1–V3） | 100% 通过 |
| 教学层（新增） | 先提示后答案、难度渐进、错题归因正确 | ≥ 95% [计划] |
| 判题层（新增） | 客观题判题与标准答案一致 | 100%（可精确验证） |
| 评分层（新增） | 主观题采分点命中可解释、可复核 | 人工抽检 ≥ 90% 一致 [计划] |
| 掌握度层（新增） | 掌握度计算可复现、单调性正确 | 100%（可精确验证） |

**总原则：自动检查必须清零**（`qiaomu-meta-skill` 第 19 条）。不得给检查器加白名单或替身来让它通过。

## 11. 指标

| 类型 | 指标 | 目标 |
|---|---|---|
| 北极星 | 周活跃学习者的"完成一次学习闭环"次数（学→练→诊断→再学） | 定义待定 |
| 教学 | 知识点讲解后同知识点题目正确率提升 | [假设] ≥ 15% |
| 测评 | 判题准确率 | 100%（客观题） |
| 诊断 | 错题归因被用户认可率 | [假设] ≥ 70% |
| 路径 | 推荐路径的完成率 | [假设] ≥ 50% |

## 12. 风险与合规

| 风险 | 等级 | 应对 |
|---|---|---|
| 被认定为"法律服务"而需资质 | 高 | 严格排除个案意见/文书/策略；输出统一教学用途声明 |
| 数据许可风险（JEC-QA 等） | 高 | 发布前逐源核实许可；不明者不入正式库；保留来源与核查记录 |
| 法条时效性（法律修订） | 中 | 建立版本校验流程，标注条文时效 |
| AI 评分误导学习者 | 中 | 强制"AI 初评 + 人工复核"双轨，标注不确定性，不给绝对分 |
| 未成年人个人信息 | 中 | 内容分级；不做敏感信息记忆；记忆可关闭可删除 |
| 模型幻觉污染教学内容 | 高 | 模型默认关闭；开启时只允许改措辞、禁止改事实；全链路回源核验 |
| 知识点体系主观性 | 低 | 标注体系版本与来源，允许教师覆盖 |
